# Job Match Search

사용자가 제공한 경력 자료를 검색 가능한 프로필로 바꾸고, 연결된 채용 MCP에서 공고를 찾아 설명 가능한 적합도 순으로 제시한다.

## 초기 연결

첫 사용, 사용자가 초기 설정을 요청한 경우, 채용 MCP 도구가 하나도 보이지 않는 경우, 인증·설정 오류가 발생한 경우에는 검색 전에 [Credential setup](references/credential-setup.md)을 읽는다.

1. Wanted, 사람인, 잡코리아 중 연결할 플랫폼을 묻고 복수 선택과 건너뛰기를 허용한다.
2. 선택한 플랫폼의 인증정보가 이미 발급되었는지 확인한다.
3. 터미널 실행 권한이 있으면 scripts/configure-credentials.mjs를 실행한다. 이 스크립트가 마스킹된 TTY 입력을 받아 저장소 밖의 권한 제한 파일에 저장한다.
4. 터미널 실행 권한이 없으면 사용 중인 에이전트의 보안 입력 UI, secret store 또는 로컬 MCP 환경변수를 안내한다. 비밀값 자체를 일반 대화로 요구하지 않는다.
5. MCP 호스트에는 비밀값 대신 scripts/run-mcp.mjs를 서버별 인자와 함께 등록한다.
6. 사용자가 설정 완료를 알리면 가장 작은 읽기 전용 조회로 연결을 검증한다. 성공 시 플랫폼 이름만 확인하고 인증값은 출력하지 않는다.
7. 실패하면 누락되거나 거부된 환경변수 이름과 해결 방법만 설명한다. 입력값, 잡코리아 발급 URL 또는 Authorization 헤더를 되풀이하지 않는다.

이미 정상 호출되는 플랫폼에는 매번 인증을 다시 묻지 않는다. 일부 플랫폼을 건너뛰거나 아직 발급받지 못했어도 연결된 플랫폼만으로 계속 검색할 수 있다.

## 입력 취급

- 대화에 첨부되거나 사용자가 경로·URL로 지정한 이력서, CV, 경력기술서, 포트폴리오만 읽는다.
- 자료를 읽을 수 없으면 재첨부나 접근 가능한 형식을 요청한다. 보이는 내용 이상을 추측하지 않는다.
- 원문, 연락처, 주소, 생년월일, 계정 식별자 등 개인정보를 MCP나 외부 검색 서비스에 보내지 않는다.
- 채용 검색에는 직무명, 기술, 경력 범위, 선호 지역처럼 최소한의 파생 조건만 전달한다.
- 자료를 별도 파일, 데이터베이스 또는 장기 메모리에 저장하지 않는다. 사용자가 명시적으로 요청한 산출물만 저장한다.

## 프로필 만들기

다음을 추출하되 각 항목을 명시, 강한 근거가 있는 추정, 미확인으로 구분한다.

- 목표 또는 최근 직무와 직급
- 총 경력과 직무별 실무 기간
- 실제 사용 근거가 있는 기술, 도구, 산업 도메인
- 프로젝트 규모, 역할, 성과와 정량 지표
- 언어, 자격, 학력 중 채용 요건 판단에 필요한 정보
- 희망 지역, 원격 여부, 고용 형태, 연봉, 비자 등 명시된 선호와 제한

사용자 자료에 목표 직무가 없으면 최근 경험에서 1~3개의 후보 직무를 제안하고 이를 가정으로 표시한다.

### 검색 전 조건 확인

희망 지역이나 세부 조건이 사용자 요청과 자료에 없으면 검색을 시작하기 전에 한 번만 묶어서 질문한다.

- 희망 지역 또는 지역 무관 여부
- 출근·하이브리드·원격 선호와 고용 형태
- 희망 직무, 산업, 연봉 또는 제외 조건 중 결과를 크게 바꿀 항목

질문할 때 답하지 않고 조건 없이 검색할 수도 있음을 함께 안내한다. 사용자가 건너뛰거나 조건 없이 검색해 달라고 하면 질문을 반복하지 않고, 지역·근무 형태를 제한하지 않은 넓은 검색을 진행한다. 이때 적용한 기본값과 미확인 조건을 결과의 검색 프로필에 명시한다.

이미 사용자가 지역 무관, 조건 무관 또는 특정 항목에 선호 없음이라고 밝혔다면 해당 항목을 다시 질문하지 않는다.

나이, 성별, 사진, 혼인 여부, 출신지, 장애, 종교 등 보호되거나 직무와 무관한 특성은 검색과 순위에 사용하지 않는다.

## 검색

1. [MCP routing](references/mcp-routing.md)을 읽고 현재 사용 가능한 채용 MCP를 식별한다.
2. 핵심 직무명과 동의어, 대표 기술을 조합해 넓은 검색을 먼저 수행한다. 이력서 문장 전체를 검색어로 쓰지 않는다.
3. 지역·경력·고용 형태 같은 확실한 필터만 적용한다. 플랫폼 코드를 모르면 코드 값을 발명하지 말고 키워드 검색이나 무필터 조회를 사용한다.
4. 한 플랫폼의 실패가 다른 플랫폼 검색을 막지 않게 한다. 실패한 출처와 이유를 결과에 짧게 밝힌다.
5. 결과가 부족하면 동의어를 바꾸거나 인접 직무로 한 번 확장한다. 필수 조건을 임의로 완화하지 않는다.
6. 마감된 공고는 제외하고, 마감 여부를 확인할 수 없으면 마감 미확인으로 표시한다.

사용자가 특정 플랫폼만 지정하면 그 범위를 지킨다. 어떤 채용 MCP도 연결되지 않았다면 필요한 서버를 알려주고 중단하며, 조회하지 않은 실제 공고를 만들어내지 않는다.

## 정규화와 매칭

- 회사명, 정규화한 공고명, 지역 또는 원문 URL이 같은 결과를 중복 후보로 본다.
- 중복 공고는 정보가 더 풍부하고 최신인 항목을 대표로 선택하되 다른 출처도 기록한다.
- 상세 내용이 필요한 상위 후보만 추가 조회해 불필요한 API 호출을 줄인다.
- [Matching rubric](references/matching-rubric.md)에 따라 평가한다.
- 공고나 사용자 자료에 없는 요건은 미확인으로 둔다. 키워드가 같다는 이유만으로 실무 경험을 확정하지 않는다.

## 결과

기본 출력은 다음 순서로 간결하게 작성한다.

1. **검색 프로필**: 목표 직무, 경력, 핵심 기술, 선호 조건과 사용한 가정
2. **추천 공고**: 상위 10개 이내의 표
3. **추천 이유**: 상위 3개에 대해 근거가 확인된 강점과 주의할 격차
4. **검색 범위**: 조회한 플랫폼, 검색어·주요 필터, 실패하거나 미확인인 범위
5. **다음 조정**: 결과를 좁히거나 넓힐 수 있는 질문 1~2개

추천 표에는 순위, 적합도, 회사/직무, 확인된 일치 근거, 격차 또는 미확인 요건, 지역·근무 형태, 마감일, 출처와 원문 링크를 포함한다. 링크가 응답에 없으면 만들지 않는다.

점수는 비교를 돕는 휴리스틱이지 합격 가능성이 아님을 명시한다. 근거가 부족할수록 단정적인 표현을 피한다.

## 권한 경계

이 스킬은 검색과 비교를 수행한다. 사용자 요청 없이 지원서를 제출하거나 계정을 만들거나 담당자에게 연락하거나 결제하지 않는다. 사용자가 지원을 요청해도 제출 직전에는 대상 공고와 전송 내용을 보여주고 별도 확인을 받는다.
